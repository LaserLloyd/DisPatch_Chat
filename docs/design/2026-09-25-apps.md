# DisPatch Apps — trusted, self-contained add-on packages

Date: 2026-09-25. Status: contract for implementation (backend and frontend halves
built in parallel against this document). Builds on `2026-09-25-tools-plugins.md`.

## Why

Tools (`kind: static|url`) are deliberately powerless: a sandboxed page with no
API access. That is right for a report, wrong for the Job Board, which has a
backend (`/api/jobs`, 1.4k lines), a board UI, a per-thread panel inside the chat
(job detail), a bot identity (`jobboard`, `agent: scout`) and locale strings — all
hand-wired across `main.py`, `main.js`, `index.html`, `app.css` and eight locale
files. An **app** is a package that carries all of that itself, so the shell only
needs a loader. The Job Board is the first app; the four builtins can follow the
same path later (out of scope now).

## Package layout

```
apps/<id>/                      # repo-shipped apps live here (deployed)
  app.yaml                      # manifest (below)
  backend.py                    # def build(ctx: AppContext) -> fastapi.APIRouter
  static/
    index.html                  # the full-page panel (framed, same-origin, trusted)
    *.js, *.css                 # the app's own assets, served at /apps/<id>/…
    thread.js                   # OPTIONAL chat-side hook (ES module, see below)
  locales/<lang>.json           # OPTIONAL, same 8 languages as the shell, flat keys
  tests/test_*.py               # pytest (collected via backend/pyproject testpaths)
  tests/*.test.js               # node --test (collected by frontend/package.json)
<DATA_DIR>/apps/<id>/            # add-on apps NOT in git — same layout; loaded only
                                # when tools.yaml carries {id, kind: app, trusted: true}
```

### `app.yaml`

```yaml
id: jobboard                    # [a-z0-9-]{1,40}; the tool id, the /apps/<id>/ path
title: Job Board
icon: clipboard                 # icon name from the shell's line-icon set, or emoji
safe: false                     # default false → operator only (Safe Mode never sees it)
order: 50                       # rail order among tools (builtins first, then apps, then static/url)
api:
  legacy_prefix: /api/jobs      # OPTIONAL: mount the router here TOO, unchanged, so
                                #   external callers (the scout agent, crons) keep working
bot:                            # OPTIONAL: a roster bot the app needs to exist
  id: jobboard
  name: Job Board
  emoji: "🎯"
  avatar: jobboard-face.png     # relative to the avatar dir; absent = letter block
  agent: scout                  # OpenClaw agent id the thread dispatches to
  visible: false                # default false: the app tile is the front door
thread_hook: true               # static/thread.js exists; mount it in that bot's threads
env:                            # OPTIONAL: env var names the backend may read (allowlist)
  - JOBS_PROFILE_PATH
```

Unknown keys are refused; `id` must be unique across tools, bots and apps.

## Backend contract

- `backend/app/apps_loader.py` (new): `discover()` scans `<repo>/apps/*/app.yaml`
  and, for each `tools.yaml` row `{id, kind: app, trusted: true}`, `<DATA_DIR>/apps/<id>/app.yaml`.
  Validates manifests (closed schema), imports `backend.py` by path
  (`importlib.util.spec_from_file_location`, module name `dispatch_app_<id>`), calls
  `build(ctx)` and mounts the returned router at `/api/apps/<id>` **and** at
  `api.legacy_prefix` if set. An app that fails to import/build is logged and
  skipped — the shell never fails to boot because of an app. Load order = manifest
  `order`, then id.
- `AppContext` (dataclass passed to `build`): `app_id`, `data_dir` (a per-app dir
  `<DATA_DIR>/apps-data/<id>/`, created 0700), `db` (the shared `Database`),
  `config` (module), `require_operator` (the shell's operator-session dependency to
  put on mutating routes), `require_access` (operator OR machine-inbound loopback —
  what `/api/jobs` uses today for the scout agent), `broadcast(frame: dict)` (WS
  broadcast to operator clients, frame type must be prefixed `app:<id>:`),
  `bot_id` (from the manifest, or None), `env` (only the allowlisted names),
  `log`.
  **Added in the implementation (2026-09-25, for the Job Board):**
  `broadcast_message(thread_id, bot_id, message)` (async; the shell's own
  `message` frame for a message the app stored via `ctx.db.add_message`) and
  `dispatch_turn(thread_id, bot_id, text) -> bool` (start the bot's agent turn,
  fire-and-forget). `/find` and `/{id}/feedback` post into the month thread and
  start the scout turn; neither is expressible through `broadcast`, whose frames
  must be `app:<id>:*`. `broadcast`, `broadcast_message` and `dispatch_turn` are
  methods; `data_dir` and `db` are properties (resolved at call time).
  Consequence for the frontend: the board's frames are now
  `app:jobboard:job_created` / `app:jobboard:job_updated` (were `job_created` /
  `job_updated`). Locales: `/apps/<id>/locales/<lang>.json` is served from the
  package's `locales/` directory (beside `static/`, per the layout above).
- Gating: every `/api/apps/<id>/…` and `/apps/<id>/…` path is in `_decoy_blocked`
  unless the app is `safe: true` (then GET/HEAD of `/apps/<id>/…` and the app's
  GET routes pass; mutations still operator-only). The loader wraps the router in a
  router-level dependency that returns the uniform decoy 403 for Safe-Mode callers
  of non-safe apps and 404 when the app is disabled in `tools.yaml`
  (`{id, kind: app, enabled: false}` — the ONLY fields honoured on a repo app row,
  plus `trusted` for a data-dir app).
- Static serving `/apps/<id>/` → `static/index.html`, `/apps/<id>/{path}` → any
  file under `static/` (same path guards as `tools.py`: strict resolve, no
  traversal/symlink escape, no hidden files, deny patterns, uniform 404, 64 MB cap,
  `Cache-Control: private, max-age=0, must-revalidate`). HTML responses carry a
  first-party CSP: `default-src 'self'; script-src 'self'; style-src 'self'
  'unsafe-inline'; img-src 'self' data: blob:; connect-src 'self'; frame-ancestors
  'self'` — NO `sandbox` (the page is trusted repo code and needs the session
  cookie to call its own API). `?v=` cache-busting is the app's own business;
  `index.html` is `no-cache`.
- Bot provisioning: on startup, for each loaded app with `bot:`, ensure the roster
  (`config.load_bots()`) has that id; if absent, append it through the existing
  single serializer (`_bot_entry`/`_write_bots`) with the manifest's fields and
  `visible: false`; if present, leave every field alone (the operator owns it).
  Log once. `GET /api/bots` behaviour is unchanged.
- `/api/tools` gains app rows: `{id, title, icon, kind: "app", enabled, safe,
  order, has_refresh: false, bot_id?, thread_hook: "/apps/<id>/thread.js"|null,
  entry: "/apps/<id>/"}`. Builtins first, then apps by `order`, then static/url.
  `GET /api/tools/<id>/status` for an app: `{id, kind: "app", enabled, mounted: bool}`.
- `tools.yaml` rows of `kind: app` may only carry `id, kind, enabled, trusted`
  (PUT refuses anything else); the Settings → Tools table shows apps as rows with
  an enabled toggle and no remove button (their package is on disk).
- Tests: `backend/pyproject.toml` `[tool.pytest.ini_options] testpaths = ["tests",
  "../apps"]` (or equivalent) so `uv run pytest` collects `apps/*/tests`.
- Deploy: the operator's deploy tool's `APP_PATHS` and `scripts/sync_from_live.py`
  `ALLOW` gain recursive entries for `apps/**` (`app.yaml`, `*.py`, `static/**`,
  `locales/*.json`, `tests/**`). The deploy tool's stale-`?v=` guard must
  cover `apps/*/static/*.js|*.css` referenced from `apps/*/static/index.html`.

## Frontend contract

- `frontend/static/js/app-sdk.js` (new, served at `/static/js/app-sdk.js`): the
  ONLY thing an app page imports from the shell. Exports:
  - `api(path, {method, body, query})` → JSON; same-origin `fetch` with
    `credentials: 'same-origin'`; a 403 `{decoy:true}` throws `DecoyError` (the
    page shows "Unlock for full access"); 4xx/5xx throw with the server's `detail`.
  - `t(key, vars)` / `ready()`: loads `/apps/<id>/locales/<lang>.json` for the
    shell's current language (read from the same localStorage key the shell uses,
    fallback `navigator.language`, then `en`), with English as fallback; `has(key)`.
  - `theme()`: applies the shell's palette + dark/light to `document.documentElement`
    (same localStorage keys the shell's no-FOUC script reads) and links
    `/static/ui-theme/…` + `/static/theme.css` the way `index.html` does; listens
    for `storage` events so a palette change in the shell re-themes the app.
  - `openThread(threadId)`, `close()`, `toast(text)`, `setTitle(text)`:
    `window.parent.postMessage({type: 'dispatch:'+name, …}, location.origin)`.
  - `onMessage(fn)`: messages FROM the shell (`dispatch:theme`, `dispatch:lang`).
  The shell (`tools.js`) listens for `message` events, accepts them ONLY when
  `event.origin === location.origin` and `event.source` is the open app frame, and
  handles `open-thread` (close the app pane, `rememberPrev` semantics apply, open
  the thread), `close`, `toast`, `set-title`.
- `tools.js`: `kind: "app"` opens in the existing `#tool-view` pane, frame
  `src = /apps/<id>/`, `sandbox` attribute REMOVED (same-origin trusted), `allow`
  none. Rail tile like a builtin (line icon by name or emoji). Deep link
  `#tool=<id>` works. Full-page (`body.tool-full`) as for every tool.
- Thread hook: when a thread whose `bot_id` equals an app's `bot_id` is opened and
  the app row has `thread_hook`, `main.js` lazy-imports that module
  (`import(/* @vite-ignore */ url)` — plain dynamic import with a `?v=` from the
  app row's `hook_version`, or none) and calls `mount({threadEl, headerEl,
  thread, api, t, openThread})`; on leaving the thread it calls the returned
  `unmount()`. The module must not import from the shell except `app-sdk.js`.
  This replaces the hard-wired `openJobDetail/closeJobDetail` imports.
- The shell drops every Job-Board-specific thing: `js/jobs.js`, `js/job-thread.js`,
  `.job-*`/`#job-*` CSS, the `jobs.*` locale namespace in all 8 files, `JOBS_ID`
  and the jobboard builtin in `BUILTINS`, `#job-board-host`, the `jobboard`
  builtin entry in `backend/app/tools.py` and `main.py` (`_JOBS_MOUNTED`,
  `JOBS_ENABLED`, `jobs_available`, the router include), `backend/app/jobs.py`,
  and the old tests (`test_jobs*.py`, `jobs.test.js`) — all of it moves under
  `apps/jobboard/`. Nothing named "jobs" remains in `backend/app/` or
  `frontend/static/js/` afterwards except the app-sdk hook plumbing.
- sw.js: `app-sdk.js` joins SHELL; `/apps/*` is network-only (never precached);
  CACHE bump.

## The Job Board app

`apps/jobboard/`: `app.yaml` as in the example above (`legacy_prefix: /api/jobs`,
bot `jobboard`/`scout`, `thread_hook: true`, env allowlist = whatever `jobs.py`
reads today — grep it). `backend.py` = today's `jobs.py` router body with its
`APIRouter(prefix="/api/jobs")` replaced by a prefix-less router returned from
`build(ctx)`; DB tables, monthly threads, `/find`, votes, feedback, tags, archive,
profile recompute all unchanged; the machine-inbound access the scout agent relies
on comes from `ctx.require_access`. `static/index.html` + `board.js` (today's
`jobs.js`, rewritten against the SDK: no shell imports, its own DOM root, its own
`board.css` carrying the moved `.job-*` rules) + `thread.js` (today's
`job-thread.js` as a hook module). `locales/*.json` = today's `jobs.*` keys,
flattened. Tests moved and adapted. Behaviour parity is the acceptance test: the
board lists months, filters, opens a job, hands off to its thread; the thread shows
the job detail panel; `POST /api/jobs/find` and `/api/jobs/{id}/feedback` from a
sessionless loopback caller still work (the scout agent path); Safe Mode gets 403
on everything.

## Out of scope

Converting DSH/StudioForge/Emails/Clients (they stay builtins; the path is now
clear), app-to-app messaging, apps registering WS frame types beyond
`app:<id>:*`, hot-reloading an app's backend, a marketplace.
