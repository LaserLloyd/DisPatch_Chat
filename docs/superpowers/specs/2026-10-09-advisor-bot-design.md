# Advisor bot — design (2026-10-09)

A fast DisPatch chat partner for advice and general conversation. It answers
straight from a model API (no OpenClaw turn), knows the owner and his projects
from a knowledge corpus that OpenClaw maintains, and hands work to OpenClaw
agents — research on its own, actions only after the owner taps Send. Every
report that comes back joins the corpus, so the bot gets better informed over
time.

## Decisions (owner, 2026-10-09)

| Question | Decision |
|---|---|
| Model | A cloud model first, a local model as fallback |
| Context | Profile always in the prompt + retrieved corpus chunks (hybrid keyword + embedding search) |
| Handoff | "Look into" requests dispatch automatically; "do" requests show a confirm card |
| Memory loop | Nightly digest of the day's advisor chats into the corpus (which OpenClaw also indexes) |
| Visibility | Unlocked only (`safe: false`) |

## Pieces

| Unit | Responsibility |
|---|---|
| `knowledge.py` | Index of the corpus directory (Markdown files are truth, the index is a cache): chunking, FTS5 keyword search, embeddings via an OpenAI-compatible `/v1/embeddings` endpoint, hybrid ranking, writing report files. |
| `advisor.py` | The turn: prompt assembly (persona + profile + retrieved chunks + history), real token streaming into the existing provisional-bubble protocol, provider fallback chain, marker handling (`[[research:…]]`, `[[handoff:…]]`), the request ledger, dispatch to OpenClaw agents, posting reports back, the nightly digest. |
| `main.py` | Routes a bot with a `advisor:` block to `advisor.run_turn`; endpoints for the confirm card, the digest trigger and status; background loop (index refresh + request watchdog). |
| frontend | Renders a handoff card (brief + Send / Dismiss) from message metadata. |
| OpenClaw | Writes `_profile.md` (a cron), indexes the corpus for its own agents, runs research (a worker agent) and actions (the lead agent). |

## Corpus

a directory set by the bot's `knowledge_dir`:

- `_profile.md` — who the owner is, preferences, current priorities. Regenerated by an OpenClaw cron; always injected. If missing, DisPatch falls back to the configured `profile_fallback` files.
- `research/<date>-<slug>.md` — one file per report, YAML front matter: `title, question, agent, request_id, created, sources`.
- `conversations/<date>-<bot>.md` — the nightly digest (one per advisor per day).
- anything else Markdown dropped in by hand or by agents.

Index: `<data>/knowledge-<hash>.db`, one per corpus directory (SQLite: files, chunks, FTS5, embedding blobs). Refreshed every 2 minutes and immediately after a report lands. Query embedding has a 2 s budget; on timeout or rig outage the search is keyword-only, never an error.

## Turn

1. Load history (existing `llm_api.build_history`).
2. Search the corpus with the latest user message (+ previous user turn) → top chunks within a ~6k-char budget, each labelled with its file title and date.
3. System prompt = persona + rules (freshness, markers) + profile + retrieved chunks + open requests.
4. Stream from the first provider in the chain that answers (the cloud model, then the local fallback). A provider that fails before the first token falls through; one that fails mid-stream ends the turn with an error.
5. Strip markers from the visible text, persist through the shared funnel (which closes the provisional bubble), then act on the markers.

## Markers

- `[[research:<agent>|<brief>]]` — dispatched at once (default: the configured research agent). The bot says something like "good idea, let me look into that".
- `[[handoff:<agent>|<brief>]]` — a card with Send / Dismiss. Nothing runs until Send (unlocked session required). Default: the configured action agent.

Each creates a row in the `requests` table of `<data>/advisor.db` (id, thread, kind, agent, brief, state, timestamps, result path). Dispatch is `openclaw agent --agent <id> --session-key agent:<id>:advisor-<rid>` in the background. The agent's final reply is the report: DisPatch writes it into `research/`, indexes it, and posts a short "back with an answer" message into the originating thread. A request that fails or times out posts a ⚠️ line instead.

## Nightly digest

`POST /api/advisor/digest` (machine-inbound: loopback or API token), run by an OpenClaw command cron: summarises each advisor thread's messages from the past day with the primary model into `conversations/<date>-<bot>.md`.

## Error handling

Every failure stops the spinner and sets the thread to `error` (same contract as `llm_api.run_api_turn`). Index or embedding failures degrade retrieval, never the turn. Dispatch failures are reported in the thread.

## Testing

Unit tests for chunking, hybrid ranking, marker parsing, the fallback chain (fake SSE servers), the request ledger, and the handoff endpoint's auth gate. Live verification: a real conversation on a scratch instance, plus a real research round-trip through an agent.
